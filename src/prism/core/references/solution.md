# Simple solution exploration

Use this reference when a meaningful redesign needs direction comparison. Stop before detailed flow, wireframe, product requirements, or technical definition.

## Entry

Move ahead when the user difficulty, desired progress, important constraints, and consequence of being wrong are understood well enough for a reversible design decision.

If one missing answer could change the solution class or create a safety or trust risk, learn first. Otherwise proceed and label the assumption that matters.

## 1. Define the job

In a few lines, state:

- what the user is trying to do;
- where the current experience fails;
- what a successful experience must make easier or clearer;
- what it must not hide or misrepresent.

Do not start from the business taxonomy or feature inventory.

## 2. Explore two or three structures

Always include a **familiar/simple pattern**:

- the established category model users are likely to recognise;
- the current pattern with its core failure removed; or
- a strong adjacent-product pattern adapted to this context.

Add one or two other directions only when they change something meaningful:

- how much the product guides or recommends;
- whether it prevents, explains, or helps recover;
- how information is sequenced;
- where user choice and confirmation occur.

Do not count visual styling, card shape, wording, or minor layout changes as separate directions.

For each direction, describe only:

- central idea;
- what becomes easier for the user;
- what the product must do;
- main trade-off;
- when the direction would be wrong.

## 3. Choose by subtraction

Prefer the direction that passes these checks with the least interface machinery:

1. Users can recognise the pattern immediately.
2. The main answer appears before explanation.
3. The next action is obvious.
4. Unavailable actions do not appear available.
5. Essential conditions appear before commitment.
6. Secondary detail can be progressively disclosed.
7. The system handles ranking, calculation, or eligibility where possible.
8. Mistakes are prevented or easy to recover from.

If the familiar/simple direction passes, it should lead. Add a more systemic layer only when it fixes a named failure the simple pattern cannot.

## 4. Keep the product role proportionate

Use the lightest role that helps:

- **Explain** when the user needs meaning or limitations.
- **Guide** when sequence prevents mistakes.
- **Recommend** when the system has enough evidence and can explain why.
- **Act** only when permission, confidence, and reversal are clear.

Do not build an ongoing system for a temporary task.

## 5. Recommend one direction

State:

- the chosen direction;
- why it is simpler and stronger;
- which useful element, if any, is retained from another direction;
- the main trade-off;
- what remains assumption-led or dependent on product, policy, operations, or technology.

Do not present all options as equally good when one clearly leads.

## Competitor and adjacent references

Treat references as pattern evidence, not authority.

Separate:

- **Adopt:** a structural behavior that improves recognition or task completion.
- **Adapt:** a pattern that needs different eligibility, trust, content, or product logic.
- **Avoid:** brand styling, unsupported behavior, or a pattern that hides consequential conditions.

## Complexity warning signs

Step back when the proposal:

- creates a dashboard for one decision;
- mirrors internal offer or service categories as separate user journeys;
- repeats the same explanation in a summary and several cards;
- adds navigation to expose information that could be inline;
- introduces multiple primary actions;
- needs extensive annotation to explain how the basic screen works;
- combines prevention, guidance, education, and recovery into one heavy surface.

## Output

Keep the response compact:

**User job and current failure**

**Directions considered**

**Recommended direction**

**Why the simpler direction leads**

**Trade-off and unresolved dependency**

When the user asked only for directions or a recommendation, stop here.
