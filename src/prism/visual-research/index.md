# Curated app-screen inspiration library

This library contains 300 user-supplied app-screen references from the Pinterest board recorded in `catalog.json`. The exported filenames were replaced with stable IDs (`ref-001` through `ref-300`), while the original title, pin URL, and image source remain in the catalog for attribution.

Use this library as curated pattern evidence and taste calibration. It is not a design system, a source of product requirements, or permission to copy another product.

Open `visual-research.html` for visual discovery. It presents every reference in a labelled box, supports search and pattern filters, and opens the selected screenshot at inspection size. Use `catalog.json` for machine-readable provenance and `screenshots/` for direct image inspection.

## How to retrieve references

1. Translate the current design need into three parts:
   - **user job:** compare, choose, understand, recover, review, track, buy, schedule, or confirm;
   - **information shape:** one object, repeated objects, before/after, progress, evidence, benefits, metrics, or instructions;
   - **state:** initial, selected, changed, loading, success, error, empty, locked, or completed.
2. Start with one or two clusters below. Use `visual-research.html` to scan the filtered candidates; search `catalog.json` only when a title or app hint could narrow the set further.
3. Open and inspect the individual image for no more than five candidates. Never infer a pattern from its thumbnail, ID, title, or cluster alone.
4. Select the two or three references that provide a useful structural alternative.
5. Decode hierarchy, grouping, density, interaction, state communication, and visual thesis. Re-express the lesson with Dopamine components and tokens.

The random source names are deliberately not used for retrieval. Stable IDs make the references portable and keep source attribution separate from pattern classification.

## Evidence quality

- **Interaction evidence:** a readable app screen or sequence showing hierarchy, actions, and state. This may influence UX structure.
- **Presentation evidence:** a phone mockup, collage, or marketing composition containing usable UI fragments. Use it to study composition or visual emphasis, not unseen behavior.
- **Mood-only evidence:** illustration, poster, cropped detail, or brand presentation without enough UI context. It may inform a visual thesis but cannot justify an interaction.

When uncertain, downgrade the evidence rather than inventing the missing behavior.

## Source and copying boundary

- Keep each selected reference tied to its `pin_url` from `catalog.json`.
- Describe observations separately from inference.
- Borrow a principle or pattern; do not trace layouts, copy text, reuse source assets, or imitate brand styling.
- Apply Tata 1mg Dopamine typography, semantic colour, spacing, components, imagery rules, and interaction states.
- A reference never overrides healthcare clarity, accessibility, user control, or the interface-principles gate.
